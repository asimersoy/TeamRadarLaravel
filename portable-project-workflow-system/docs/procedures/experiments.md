# Experiments

## Trigger

Use for workflow, batching, quality, cost, performance, search-tool, model, or
implementation comparisons intended to support a later decision.

## Design

Before starting, record:

- hypothesis and decision to be informed;
- comparable units and controlled variables;
- known differences in sensitivity, complexity, or liability;
- measurements and quality rubric;
- start/stop boundaries and interruption handling;
- what the experiment does not authorize.

## Execution

1. Use comparable work and the same acceptance standard.
2. Separate active working time from wall-clock time when tooling permits; if
   it does not, label wall-clock data and interruptions honestly.
3. Attribute shared setup, shared QA, and cross-condition corrections rather
   than charging them silently to the later condition.
4. Record exchanges, correction rounds, defects, review effort, elapsed time,
   and residual quality issues.
5. Do not lower the quality bar to finish a condition.
6. Analyze uncertainty and confounders before recommending a default.

## Completion Evidence

Report raw measurements, allocation method, interruptions, quality outcomes,
limitations, result, and recommended decision. The owner decides whether the
workflow or tool changes.
